# 系统功能概览 - 答辩问答精简版

## 第一部分：整体架构

### Q1：系统整体架构是怎样的？

**口述回答：**

我们采用**移动端+PC端双端联动**的架构：

**移动端（学生使用）：**
- 生活服务：外卖订餐、跑腿代办、二手交易
- 预约管理：自习室、教室、医务、心理咨询
- 社交互动：校园圈子、活动报名、IM即时通讯
- AI助手：智能预约、学习建议、图书推荐

**PC端（管理员使用）：**
- 服务管理：食堂、跑腿、医务、心理中心后台
- 数据看板：订单统计、资源利用率、异常告警
- 内容治理：圈子审核、活动管理、举报处理
- 报表分析：桑基图、热力图、趋势分析

**核心创新：双端数据打通，实现"学生用得爽、管理看得清、问题管得住"**

---

### Q2：为什么要做移动端+PC端，而不是只做一端？

**口述回答：**

**单端的问题：**

只做移动端：
- 学生能用，但管理员看不到数据
- 出了问题（如食堂投诉）无法及时处理
- 资源利用率低（无法优化调度）

只做PC端：
- 管理员能看数据，但学生不方便用
- 没有移动化，使用率低
- 数据来源少，分析价值低

**我们的双端联动：**

移动端产生数据 → PC端分析优化 → 反哺移动端体验

**举例：**
1. 学生APP预约座位（移动端）
2. PC看板发现A区利用率89%，B区仅30%（PC端）
3. 系统智能引导学生到B区（移动端优化）
4. 整体利用率从60%提升到75%（闭环）

## 第二部分：移动端功能

### Q4：外卖订餐功能和美团饿了么有什么不同？

**口述回答：**

**主要区别：**

**1. 校园场景专属**
- 只对接校内食堂（不是社会餐厅）
- 配送距离短（5-10分钟），效率高
- 价格便宜（食堂定价，无溢价）

**2. IM深度集成**
- 订单详情页直接"联系食堂"
- 遇到问题（如忘带卡）立即沟通
- 对话中显示订单信息（业务锚点）

**3. 排队预测**
- 实时显示窗口排队人数
- 预测等待时间（误差±2分钟）
- 推荐错峰时段（"11:30人少，奖励5积分"）

**4. 学生骑手**
- 接单学生自己配送
- 赚零花钱（每单3-5元）
- 熟人配送，更可靠

**特色功能：**

- **IM沟通：**对话中显示任务详情
- **信用评分：**爽约扣分，限制接单

**双赢：**
- 发单方省时间
- 接单方赚零花钱（贫困生勤工俭学）

### Q6：二手交易为什么不用闲鱼？

**口述回答：**

**闲鱼的问题：**
- 面向全社会，校园物品淹没在海量商品中
- 陌生人交易，信任度低
- 异地交易，物流成本高

**我们的优势：**

**1. 校园专属**
- 只有本校学生能看到
- 同学交易，信任度高
- 同城线下交易，面交验货

**2. IM无缝对接**
- 看到商品→点击"联系卖家"→直接聊天
- 对话中显示商品卡片（图片、价格、位置）
- 议价、约时间、确认交易，一气呵成

**3. 圈子引流**
- 发布二手商品自动进入"二手市场圈子"
- 圈子内点赞、评论、转发
- 流量更大

**4. 安全保障**
- 实名认证（学号）
- 信用评分
- 举报机制

### Q7：自习室预约的核心功能是什么？

**口述回答：**

**五大核心功能：**

**1. 实时查询**
- 显示各楼层空座位数量
- 座位分布图（可视化）
- 绿色=空闲，红色=已占

**2. 快速预约**
- 选时间段（2小时/4小时/全天）
- 选偏好（靠窗、安静、有电源）
- AI推荐前5个最合适座位

**3. 冲突检测**
- 毫秒级检测时间冲突
- 乐观锁+Redis，准确率99.5%
- 避免多人预约同一座位

**4. 候补机制**
- 满座时加入候补队列
- 按优先级排序（等待时间+信用分）
- 有人取消自动递补通知

**5. 超时释放**
- 预约后15分钟未签到自动释放
- 释放后候补用户立即收到推送
- 提高座位利用率（30%→89%）

### Q8：AI助手具体能做什么？

**口述回答：**

**三大场景：**

**场景1：智能预约座位**

用户："帮我找个明天下午的自习室"

AI流程：
1. 分析用户偏好（80%提到"靠窗"，70%提到"安静"）
2. 查询明天下午空座位
3. 按偏好匹配度排序
4. 推荐："A101座位（靠窗、安静、有电源）最适合您，要预约吗？"

**场景2：学习建议**

用户："我最近学习效率好低"

AI分析：
- 查看预约记录：最近常在晚上学习
- 查看签到时长：平均1.5小时就走
- 建议："您晚上学习效率低，建议改到上午9-11点，历史数据显示您上午平均学习3小时"

**场景3：图书推荐**

用户："推荐几本算法书"

AI：
- 分析借阅历史：借过《数据结构》《算法导论》
- 协同过滤：和你相似的人还借了《算法竞赛入门》
- 推荐："根据您的阅读偏好，推荐《算法竞赛入门》，B205架，目前可借"

**核心：多轮对话+偏好学习+业务深度集成**

### Q13：资源利用率从30%到89%是怎么做到的？

**口述回答：**

**改进前的问题（30%）：**

1. **占座不来（20%浪费）**
   - 学生预约座位后不来
   - 座位空着但显示"已占用"

2. **信息不透明**
   - 不知道哪里有空座
   - 宁可不去也不愿意到处找

3. **冲突频发**
   - 多人预约同一座位
   - 产生纠纷，不敢用系统

**我们的五大措施：**

**措施1：超时释放（+20%）**
- 15分钟未签到自动释放
- 候补队列自动递补
- 占座浪费从20%降到2%

**措施2：信息透明（+15%）**
- 实时显示空座数量和位置
- 座位分布图可视化
- 学生愿意来了，访问量+300%

**措施3：冲突检测（+10%）**
- 系统级别冲突检测，准确率99.5%
- 先到先得规则明确
- 纠纷消除，信任度提升

**措施4：候补机制（+8%）**
- 满座时进入候补队列
- 有人取消自动递补
- 高峰期也能充分利用

**措施5：积分激励（+6%）**
- 守信用户积分高，优先级高
- 爽约扣分，限制权限
- 签到率从80%提升到95%

**总计：20+15+10+8+6=59%提升**

**验证：同期A/B对比**
- A区（用系统）：利用率63%
- B区（传统管理）：利用率31%
- 提升100%

### Q14：系统如何保证数据安全？

**口述回答：**

**五层防护：**

**第1层：传输加密**
- 全站HTTPS（TLS 1.3）
- 敏感数据端到端加密

**第2层：存储加密**
- 手机号、身份证等AES-256加密
- 密码bcrypt哈希（不可逆）

**第3层：访问控制（RBAC）**
- 学生：只能看自己的数据
- 食堂管理员：只能看自己食堂订单
- 校级管理员：看汇总数据，不能看个人详情

**第4层：数据脱敏**
- 管理员查看：学号显示"202101****"
- 导出报表：手机号显示"138****5678"

**第5层：操作审计**
- 所有敏感操作记录日志
- 包括：谁、何时、访问了什么、是否成功
- 日志不可篡改，定期审计

**合规：符合《个人信息保护法》《网络安全法》**

### Q：IM集成网易云信，如果云信停服怎么办？

**回答：**

风险可控：

1. **大厂稳定性：**网易是大厂，停服概率极低，且会提前通知
2. **抽象层设计：**我们做了IM接口抽象层，切换供应商只需改实现类，业务逻辑不受影响
3. **数据备份：**核心消息同步到我们数据库，不完全依赖云信

这是使用任何云服务都要面对的问题，关键是做好风险管理。

### Q：资源利用率89%是试点数据，全校推广能达到吗？

**回答：**

89%是试点学院（管理最好）的数据，全校平均63%，更保守也更真实。

**原因：**
- 试点学院学生配合度高
- 全校推广会有推广期（需要培养习惯）

**预期：**
- 第1个月：50%（接受度提升）
- 第3个月：60%（习惯养成）
- 第6个月：65%（稳定运行）

即使是65%，相比改进前30%，也提升了117%。

### Q：PC端功能这么多，管理员会不会用不过来？

**回答：**

我们设计了管理员分级和权限隔离：

**三级管理员：**
1. **一级（食堂管理员）：**只看自己食堂的订单和数据，功能简单
2. **二级（学院管理员）：**管理本学院的圈子、活动，权限适中
3. **三级（校级管理员）：**看全校数据看板，但也是分模块的

**关键设计：**
- 每个管理员只看自己需要的数据（不会被海量信息淹没）
- 异常自动告警（不用盯着看，有问题自动通知）
- 一键导出报表（不用手动统计）

实测：食堂管理员每天只需要10分钟处理PC端事务。
